# INC-0002 - Nginx Web Service Outage

## Environment
- Lab: Personal VMware Ubuntu Server 24.04 LTS
- Hostname: dc-labsrv01
- Server IP: 192.0.2.10
- Service: Nginx 1.24.0
- Client: Ryans-Mac-mini.local
- Incident type: Controlled service outage simulation

## Incident Summary
Nginx was intentionally stopped to simulate an application service outage. HTTP connectivity failed while the service was inactive. The service was subsequently restarted and HTTP connectivity was verified locally and from a remote Mac mini client.

## Impact
- Nginx was unavailable during the controlled test.
- HTTP requests to TCP port 80 were refused.
- Impact was limited to the personal homelab.
- No production users or WestJet systems were affected.

## Timeline (UTC)
- 2026-11-01 14:26:49 - Nginx initially started.
- 2026-11-01 18:15:11 - Nginx intentionally stopped.
- After shutdown - systemctl confirmed inactive (dead).
- After shutdown - curl returned connection refused on 127.0.0.1:80.
- After shutdown - ss showed no TCP port 80 listening socket.
- 2026-11-01 18:34:08 - Nginx restarted successfully.
- 2026-11-01 18:35:16 - Local HTTP request returned 200 OK.
- 2026-11-01 18:36:06 - HTTP request to server LAN IP from the Ubuntu VM returned 200 OK.
- 2026-11-01 18:37:30 - Remote Mac mini HTTP request returned 200 OK.

## Investigation
1. Checked service status with systemctl status nginx.
2. Reviewed systemd shutdown events.
3. Tested HTTP connectivity with curl.
4. Inspected listening TCP sockets with ss.
5. Verified service status and HTTP response after restoration.

## Root Cause
The Nginx service was deliberately stopped using systemctl as part of a controlled lab exercise. As a result, no process was listening on TCP port 80 and connection attempts were refused.

The shutdown was clean, with exit status 0/SUCCESS. This was not an unexpected application crash.

## Resolution
Started Nginx using sudo systemctl start nginx.

## Verification
- systemctl reported active (running).
- New Nginx master PID: 3034.
- Local HTTP request returned 200 OK.
- Server LAN IP HTTP request returned 200 OK.
- Mac mini remote HTTP request returned 200 OK with the expected default Nginx HTML page.

## Observed Duration
- Service stop to service restart: 18 minutes 57 seconds.
- Service stop to first recorded successful HTTP test: 20 minutes 5 seconds.
- Remote HTTP verification completed 22 minutes 19 seconds after shutdown.

These are observation intervals from the lab, not measured production outage or SLA metrics.

## Prevention and Lessons Learned
- Monitor service state and application endpoint health.
- Review system logs before taking corrective action.
- Distinguish a clean service shutdown from a crash.
- Confirm listening ports when investigating connection failures.
- Verify recovery from a remote client, not only on the server.
- In production, investigate the reason for unexpected shutdowns and follow approved incident and change procedures.
