# INC-0001 — HTTP 404 Resource Investigation

**Environment:** Ubuntu Server 24.04 LTS / Nginx 1.24.0 / VMware Workstation

**Incident Type:** HTTP Resource Not Found (Lab Simulation)

**Status:** Resolved

**Severity:** Low — Controlled Lab Exercise

**Date:** November 1, 2026

## 1. Issue Summary

An HTTP GET request to `/incident-test-404` returned a 404 Not Found response. The issue was intentionally reproduced in a controlled homelab environment to practice troubleshooting and incident response.

## 2. Investigation

- Verified the HTTP 404 response in the Nginx Access Log.
- Inspected the Nginx default site configuration.
- Confirmed the document root was `/var/www/html`.
- Confirmed the `try_files $uri $uri/ =404` directive.
- Checked the requested file path and found that the file did not exist.

## 3. Root Cause

The requested resource was missing from the configured document root. Nginx returned HTTP 404 according to its configured file lookup rules.

## 4. Resolution

Created `/var/www/html/incident-test-404` with a test response message.

## 5. Verification

- Local `curl` request returned HTTP 200 at 17:12:42 UTC.
- Mac mini browser request returned HTTP 200 at 17:12:56 UTC.
- Nginx Access Log confirmed successful responses.
- A subsequent HTTP 304 response indicated successful browser cache validation.

## 6. Lessons Learned

HTTP 404 does not necessarily indicate a web server outage. Effective troubleshooting requires examining the HTTP response, application configuration, file system, and access logs before identifying the root cause.

**Outcome:** Controlled incident resolved and verified through local and remote HTTP requests.
